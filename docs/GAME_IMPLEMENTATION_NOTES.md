# Botanica M5–M11 implementation notes

## Initial audit
Existing pure packages: genetics/rules resolve and breed versioned genomes; renderer composes original SVG primitives. Fastify uses PostgreSQL transactions and tracked SQL migrations; plants and breeding_events already carry owner IDs. React has laboratory, breeding, collection, lineage inspectors and image/JSON exports. Compose exposes only web on port 8155, including LAN access for the configured Cloudflare tunnel. Existing .env is preserved.

Implementation batches: M5–M7 accounts/scoping, greenhouse and integer economy; M8–M10 progression, paid breeding and bounded worker reconciliation; M11 game presentation and one final regression/integration/browser smoke. Existing sandbox rows remain owned by their original demo UUID and become explicitly read-only examples. Designed laboratory plants remain usable studies but are excluded from game sale/breeding rewards. No database reset or volume deletion.

## Shipped implementation

- **M5**: username/password registration/login, Argon2id, opaque hashed sessions (30 days), CSRF/origin checks, bounded process-local auth throttling, logout and five one-use recovery codes. Account creation atomically grants 120 coins, three starter seeds and a four-slot house. Owned reads/mutations use the authenticated player ID.
- **M6–M7**: greenhouse home with original SVG pots/plants, responsive rail/bottom navigation and persistent HUD. Seed inventory, server-priced purchases, confirmed specimen sale, favorites/protection and a signed integer coin ledger. Receipt keys make monetary requests replay-safe. Harvest yields a plant plus one recycled starter seed; coins come from sales and distinct discovery/quest rewards.
- **M8**: persisted UTC growth (20-second first crop, then 120/300/720 seconds), 12 handcrafted one-time goals, XP-derived levels, slot expansions, lamp, irrigation, second greenhouse and three real research unlocks. Lamp reduces remaining and future growth by 10%; irrigation reduces gardener intervals from 120 to 96 seconds.
- **M9**: existing engine wrapped in paid level-3 breeding (75 coins), with two distinct owned mature game plants, immutable parent lineage and replayed stored outcomes. Instant offspring reuses the original engine; no extra breeding timer or invented probability display. Discovery uniqueness uses the resolved species/catalog/phenotype signature, not a rarity roll.
- **M10**: hire/assign gardeners and breeders, default paused. Policies repeat_crop, repeat_cross and researched target_trait use real seeds/coins/parents. Targets protect matching offspring without changing odds. A player-row lock serializes reconciliation and manual spending; chronological event simulation is capped at 100 intervals/24 hours per calculation. Persisted cursors retain surplus time. Blocked intervals advance without rewards; new resource purchases cannot fuel historical pending work. Per-worker logs reconcile to the combined report. Auto-sale starts off, only considers newly harvested Common duplicates and excludes favorites, protected plants, first discoveries and the last specimen of a species. Breeders keep all offspring.
- **M11**: forest/parchment/gold shell, tactile growing slots, live countdown, discovery reveal, next-goal tracker, explained locks, account/reduced-motion preferences, compact mobile navigation and persistent offline summary. Existing laboratory, renderer atlas, owned collection filters, inspectors, provenance and JSON/SVG/PNG exports remain. `/examples` and reference detail routes retain the old archive read-only, including genomes, ancestry and exports; pagination includes legacy records beyond the 100 demos.

## Migration and environment

`0003_game_foundation.sql` is additive for account/game data. It replaces only the breeding request uniqueness constraint with owner+request uniqueness. No existing plant IDs, genomes, versions, owners or ancestry are migrated away. Existing sandbox rows keep their original owner, which has no account password. Designed studies in real accounts remain separate from salable/breedable game plants. PostgreSQL volumes were retained throughout.

The existing `.env` was not edited. `HOST_PORT=8155` and `PUBLIC_DOMAIN=http://localhost` remain. Optional `PUBLIC_ORIGINS` is passed through Compose; its explicit defaults include local, configured LAN and public HTTPS origins. See DEPLOYMENT.md for Vite/other deployments. No additional secret or service is required. Argon2 is the only new runtime dependency.

## Practical limits

One fictional species is inherited from M0–M4; no additional species or hybrid rules were invented. Workers calculate on relevant authenticated requests/15-second state refresh, without a daemon. Large backlogs require subsequent bounded batches. Throttle counters are local to the single API process and reset on restart; no distributed limiter is claimed. Recovery codes are shown once and consumable; rotation/self-service account deletion and sound are not implemented. Registration does not require email. No paid currency, runtime generation services, trackers or multiplayer were added.

Final follow-up: the rebuilt 360px HUD measures 103px tall, with coin/seed/player groups on the same row and zero overflow (artifacts/m11/mobile-final.json and greenhouse-mobile-final.png). Public HTTPS health returns connected JSON. A final SQL audit confirms the legacy checksum still matches, no player has negative coins, every player's balance equals their signed ledger total, and no QA worker remains enabled (artifacts/m11/final-data-check.json). Only temporary test Compose containers/network were removed; the application remains running. All M5–M11 gates are complete.
